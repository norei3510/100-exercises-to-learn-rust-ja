# 依存関係

パッケージは、`Cargo.toml` ファイルの `[dependencies]` セクションに他のパッケージを列挙することで、それらに依存できます。\
依存関係を指定する最も一般的な方法は、名前とバージョンを指定することです。

```toml
[dependencies]
thiserror = "1"
```


これにより、`thiserror` が **最小** バージョン `1.0.0` の依存関係としてパッケージに追加されます。
`thiserror` は、Rust の公式パッケージレジストリである [crates.io](https://crates.io) から取得されます。
`cargo build` を実行すると、`cargo` はいくつかの段階を経て処理されます。

- 依存関係の解決
- 依存関係のダウンロード
- プロジェクトのコンパイル（自身のコードと依存関係）

プロジェクトに `Cargo.lock` ファイルがあり、マニフェストファイルに変更がない場合は、依存関係の解決はスキップされます。
依存関係の解決が正常に完了すると、`cargo` によってロックファイルが自動的に生成されます。このファイルには、
プロジェクトで使用されるすべての依存関係の正確なバージョンが含まれており、異なるビルド（例：CI）においても
一貫して同じバージョンが使用されることを保証するために利用されます。複数の開発者でプロジェクトに取り組んでいる場合は、
`Cargo.lock` ファイルをバージョン管理システムにコミットしてください。

`cargo update` を使用すると、すべての依存関係を最新の（互換性のある）バージョンに更新して `Cargo.lock` ファイルを更新できます。

<a id="path-dependencies"></a>

### パス依存関係

**パス**を使用して依存関係を指定することもできます。これは、複数のローカルパッケージを扱っている場合に便利です。

```toml
[dependencies]
my-library = { path = "../my-library" }
```


パスは、依存関係を宣言しているパッケージの `Cargo.toml` ファイルからの相対パスとなります。

### その他のソース

<a id="dev-dependencies"></a>

## 開発用依存関係

開発時にのみ必要となる依存関係（つまり、`cargo test` を実行する際にのみ取得される依存関係）を指定することもできます。\
これらは `Cargo.toml` ファイルの `[dev-dependencies]` セクションに記述します。

```toml
[dev-dependencies]
static_assertions = "1.1.0"
```


本書では、テストを簡潔にするために、こうした依存関係をいくつか使用しています。
