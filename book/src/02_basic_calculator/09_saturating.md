# ケースごとの挙動

`overflow-checks` は粗いツールであり、プログラム全体に影響を与えるグローバル設定です。\
コンテキストに応じて整数オーバーフローの処理を変えたい場面がよくあります。場合によっては
ラップが適切な選択となることもあれば、パニックさせる方が好ましいこともあります。

<a id="wrapping_-methods"></a>

## `wrapping_` メソッド

`wrapping_` メソッド[^method]を使用することで、演算ごとにラップ演算を選択できます。\
例えば、`wrapping_add` を使用して2つの整数をラップ付きで加算できます：

```rust
let x = 255u8;
let y = 1u8;
let sum = x.wrapping_add(y);
assert_eq!(sum, 0);
```


<a id="saturating_-methods"></a>

## `saturating_` メソッド

あるいは、`saturating_` メソッドを使用して**飽和演算**を選択することもできます。\
飽和演算では、値がラップされる代わりに、その整数型の最大値または最小値が返されます。
例えば：

```rust
let x = 255u8;
let y = 1u8;
let sum = x.saturating_add(y);
assert_eq!(sum, 255);
```


`255 + 1` は `256` であり、`u8::MAX` より大きいため、結果は `u8::MAX` (255) となります。\
アンダーフローの場合はその逆になります。`0 - 1` は `-1` であり、`u8::MIN` より小さいため、結果は `u8::MIN` (0) となります。

飽和演算は `overflow-checks` プロファイル設定では利用できず、演算を行う際に明示的に選択する
必要があります。

[^method]: メソッドは、特定の型に「紐付けられた」関数と考えることができます。
メソッド（およびその定義方法）については、次の章で解説します。
